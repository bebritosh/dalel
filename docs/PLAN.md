### Решения, принятые в ходе сборки
- SQLModel на Python 3.14: не используем `from __future__ import annotations` в таблицах; `datetime` хранится как UTC-aware (требование UTCDateTime этого sqlmodel).
- У `Fact` добавлено поле `grounded` (отдельно от `confirmed_by_user`), чтобы V1 оставалась честной после подтверждения.
- Telegram JSON — вырезан из MVP (оставлен только WhatsApp txt). Проверки — V1–V4 (не V1–V8).
- Проверки (checks) и недостающее (missing) считаются «на лету» в GET-эндпоинтах; события (Event) персистятся.
- LiveProvider (Anthropic) реализован на httpx без нового SDK. По умолчанию `LLM_MODE=fixture`.
- Фронтенд: Tailwind v4 + обвязка (@vitejs/plugin-react, @types/react(-dom), typescript-eslint, @eslint/js), Playwright (dev) для скриншотов — одобрено пользователем.

## Главные инварианты (красные линии, нарушать нельзя)
1. LLM возвращает только значения и `line_ids`. Текст строк и bbox копирует код из `OcrLine`.
2. Каждое число и дата в претензии = подтверждённый факт или дата события. Иначе экспорт блокируется (422 + список расхождений).
3. Правовые нормы только из `rules/legal_refs.json`. Модель их не пишет. Файл заполняем заглушками `unverified: needs lawyer review`, без выдуманных статей. В тексте — пометка «[норма уточняется юристом]».
4. Поле попадает в претензию только при `confirmed_by_user = true`.
5. Содержимое документов не пишется в логи. Имена файлов на диске — только uuid.

## Решения (принятые мной)
1. **PaddleOCR убираем.** На Windows + Python 3.14 ставится болезненно (paddlepaddle не имеет стабильных колёс под 3.14). Остаётся только Tesseract за интерфейсом `OcrEngine` — вторую реализацию можно добавить позже без переписывания.
2. **PDF обрабатываем через PyMuPDF (`pymupdf`)** — и встроенный текст, и растеризация одной библиотекой, без внешнего Poppler (меньше зависимостей на Windows). Требует одобрения как новая зависимость.
3. **`FixtureProvider` — режим по умолчанию в dev и тестах** (`LLM_MODE=fixture`). Live включается явно. Это держит тесты и демо офлайн и стабильными.
4. **Pydantic-схемы отдельно от SQLModel-моделей** (папки `app/models` и `app/schemas`), роутеры только разбирают запрос, логика — в `app/services`.
5. **Хранилище:** SQLite-файл в `data/`, файлы документов в `data/cases/{case_id}/{uuid}.{ext}`. Тесты — через временные папку и БД (pytest fixtures).
6. **Аутентификация упрощённая:** `access_token` на дело, сверка заголовка `X-Case-Token`, несовпадение → 404 (не раскрываем существование дела). Без пользователей/логина — на MVP избыточно.
7. **PDF-экспорт — опциональная деградация:** DOCX всегда; PDF только если найден `soffice`, иначе честное сообщение. Демо живёт на DOCX.
8. **Тесты:** `pytest` + `httpx`/`TestClient`. Для каждого сервиса — свои тесты.
9. **`legal_refs.json` — только заглушки** с `unverified: needs lawyer review`. Никаких придуманных номеров статей.
10. **Фронтенд без `docs/design.md`:** сделаю чистый минималистичный UI на Tailwind (спокойная палитра, акцент на читабельности претензии и подсветке чека). Если дашь дизайн-файл — переориентируюсь.

## Что кажется нереалистичным за 5 дней (и что предлагаю урезать)
- **25 синтетических дел с реалистичным шумом (Фаза 5).** Генерация правдоподобных «грязных» чеков и доведение OCR до приличной точности на них — отдельный большой кусок. Предлагаю **8–10 дел**, из них 3 «чистых» (хорошая точность) и несколько «шумных» для честного показа границ.
- **Качественный OCR на казахском по зашумлённым чекам.** Tesseract на наклонённых/бликующих чеках будет слабым. Предлагаю: **fixture-режим — основной путь демо**, live-OCR показываем «как есть, скромно», и честно это называем.
- **PaddleOCR.** Убрать совсем (см. Решения №1).
- **PDF-экспорт через LibreOffice как обязательный.** Для демо достаточно DOCX. PDF — «если успеем / если поставлен LibreOffice».
- **Полная эвристика событий из переписки (Telegram JSON + WhatsApp txt).** Оба парсера сделаю, но распознавание «обращение/ответ/отказ» будет грубым и всегда `needs_review` — это честно и достаточно для MVP. Умную классификацию не обещаю.

**Предлагаемый порядок урезания, если время кончится:** PDF-экспорт → Telegram-парсер (оставить только WhatsApp) → сократить число синтетических дел → часть проверок V5–V8.
