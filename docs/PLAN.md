# DÄLEL — план реализации (факт на 26.11.2026)

> Конструктор доказательной претензии по некачественному товару (Казахстан). На демо — только синтетические данные.
> Перед правками читай [CLAUDE.md](../CLAUDE.md) и этот файл. История по дням — [PLAN_TODAY.md](PLAN_TODAY.md); решения — [DECISIONS.md](DECISIONS.md); запуск — [HANDOFF.md](HANDOFF.md).

## Красные линии (инварианты, нарушать нельзя)
1. LLM возвращает только значения и `line_ids`. Текст строк и координаты копирует код.
2. Число/дата в претензии — только подтверждённый факт или дата события. Иначе guard блокирует экспорт (422).
3. Правовые нормы — только из `rules/legal_refs.json`. Модель их не пишет.
4. Поле идёт в претензию только при `confirmed_by_user=true`.
5. Фикстуры (`*.layout.json`, `handmade_*`) нельзя выдавать за реальный OCR/ответ модели. `.env` и реальные данные не коммитить.

## Что реализовано (подтверждено прогоном или коммитом)
### Бэкенд
- Дела: создание/получение/удаление, доступ по токену (`X-Case-Token`), файлы под uuid-именами.
- Загрузка: **jpg, png, pdf, txt, json, mp4**, лимит **15 МБ** (`app/core/storage.py`).
- OCR: режимы **fixture / tesseract / auto** (`OCR_ENGINE`), EXIF-поворот, предобработка; `TESSERACT_CMD` для пути к Tesseract.
- Извлечение с **grounding**: провайдеры fixture / openai / live (Anthropic) / rules; режим `LLM_MODE=auto`. LLM отдаёт только значения+`line_ids`, grounding проверяет наличие в указанных строках.
- Подтверждение фактов (`PATCH /facts`), раздельные `grounded` и `confirmed_by_user`.
- Проверки: **V1–V4** (grounding, дата, сумма=сумме позиций, порядок событий); **P1–P4** качество фото на Pillow (разрешение, размытость, экспозиция, EXIF-дата), только warning; **M1–M5** недостающее.
- Претензия: текст только из подтверждённых фактов + дат событий; **guard и по исходному тексту, и по финальному тексту готового DOCX** (422 при неподтверждённом числе/дате), запрет остаточных плейсхолдеров.
- Экспорт **DOCX** (санитизация недопустимых XML-символов из OCR); **PDF через LibreOffice** (тот же DOCX → `soffice --convert-to pdf`), без LibreOffice — честный **503**.
- Авто-миграция БД на старте (`ADD COLUMN`), удалять `data/dalel.db` не нужно; `scripts/reset_db.py` — полный сброс.
- Тесты: `tests/` (парсеры чата, guard, export DOCX/PDF, миграция, фото, видео mp4, E2E WhatsApp+Telegram, нормы) — 92 passed.

### Переписка и хронология
- **WhatsApp** txt: форматы Android и iOS, многострочные, пропуск системных строк.
- **Telegram** `result.json`: пропуск служебных, текст строкой/фрагментами.
- События из словаря **`rules/chat_events.yaml`** (не модель): contact / reply / refusal, каждое с `message_id` и `document_id`, `needs_review=true`; без источника не создаётся. Хронология из обоих источников.

### Правовые нормы
- 6 статей Закона РК «О защите прав потребителей» из `rules/legal_refs.json` (`citation/text/source_url/checked_at`), **`lawyer_reviewed=false`** (в UI пометка). Модель их не пишет; претензия копирует дословно; guard пропускает только точные строки ссылок.

### Фронтенд
- Три экрана (загрузка → проверка → претензия); кликабельные суммы/даты с подсветкой строки чека; плашка источника (fixture/tesseract/openai/rules); mock- и http-режимы; статическая mock-сборка (`build:mock`).
- Языки: **RU / EN / KK** (по умолчанию EN). Казахский — черновой перевод (коммит `383df20`), нужна проверка носителя; текст претензии и DOCX/PDF остаются на русском.
- Статус по умолчанию **«Не отправлено»**; кнопка **«Я отправил(а) претензию продавцу»** фиксирует действие пользователя и запускает отсчёт срока ответа (`/mark-sent`), счётчик дней корректный (коммиты `655fba3`, `709d355`).
- **Чек-лист «Что приложить»** (M1–M5 из `/missing`) на экране претензии (коммит `4ef5a45`).
- Адаптив 1440/390 без горизонтального скролла; высота экрана претензии ограничена (коммит `b1f2aad`).

### Eval
- `eval/run_eval.py --mode rules|openai|auto`. Прогон **rules** (офлайн, с Tesseract) воспроизведён: grounding 100%, галлюцинации 0%, guard 9/9, events_ok 100%. Цифры **openai** не воспроизведены (нет `OPENAI_API_KEY`).
