# DÄLEL — как запустить (Windows)

## Что это
Прототип конструктора претензий по некачественному товару. Бэкенд (FastAPI) +
фронтенд (React/Vite). Данные демо синтетические. OCR и ответы LLM на демо берутся
из офлайн-фикстур (см. «Про фикстуры» ниже) — интернет не нужен.

## Требования
- Python 3.14 (проект проверен на 3.14.3; подходит 3.11+).
- Node.js 20+ (проверено на 24) и npm.
- Tesseract и LibreOffice НЕ нужны для демо (OCR из фикстур, экспорт только DOCX).

## Первая настройка (один раз)
Бэкенд, из корня репозитория:
```
py -3 -m venv .venv
.venv\Scripts\python -m pip install --only-binary=:all: -r requirements.txt
```
Фронтенд:
```
cd frontend
npm install
```
Шаблон претензии (`templates/claim.docx`) и демо-фикстуры (`eval/fixtures/`, `eval/cases/demo-001/`) уже в репозитории. Пересоздавать их нужно, только если менялся генератор:
```
.venv\Scripts\python scripts\make_claim_template.py
.venv\Scripts\python scripts\make_demo.py
```

## Запуск (3 команды)
Открыть два терминала.

Терминал 1 — бэкенд (из `d:\dalel`):
```
.venv\Scripts\python -m uvicorn app.main:app --reload
```
Терминал 2 — фронтенд (из `d:\dalel\frontend`):
```
npm run dev
```
Открыть в браузере: `http://localhost:5173`

(Третья «команда» — открыть браузер. Бэкенд на `http://127.0.0.1:8000`, Swagger — `/docs`.)

## Демо-сценарий
1. На экране «Новое дело» перетащить два файла из `eval\cases\demo-001\`:
   `receipt.png` (тип «Чек») и `chat.txt` (тип «Переписка»). Нажать «Разобрать».
2. На экране проверки подтвердить поля (минимум: продавец, дата покупки, сумма).
   Справа — хронология и «Чего не хватает».
3. На экране претензии: клик по сумме/дате подсвечивает строку на чеке.
   «Скачать DOCX» сохраняет претензию. «Отправлено продавцу» запускает таймер 10 дней.

## Режим без бэкенда (для слайдов/жюри)
```
cd frontend
set VITE_API_MODE=mock
npm run dev
```
Весь сценарий работает на синтетических данных, сервер не нужен. Если порт 5173 занят, vite выберет следующий свободный (5174, 5175…) — смотри адрес в его выводе.

## Про фикстуры (честно)
- `eval\fixtures\{sha}.layout.json` — это РАЗМЕТКА генератора чека (истинные строки и
  координаты), а НЕ результат реального OCR. Так демо детерминировано и офлайн.
- `eval\fixtures\handmade_{sha}.json` — РУЧНОЙ ответ извлечения (нет ключа LLM на демо),
  помечен префиксом `handmade_` и полем `_source`. Это не реальный ответ модели.
- Живой OCR (Tesseract, `OCR_ENGINE=tesseract`) и живой LLM (Anthropic, `LLM_MODE=live`)
  подключаются переменными в `.env`, когда будут установлены/появится ключ.

## Почему нет PDF
Экспорт PDF требует LibreOffice headless. В этой версии отдаётся только DOCX; кнопки PDF
нет осознанно. DOCX открывается в Word/LibreOffice и готов к печати.
