# DÄLEL

Конструктор доказательной претензии по некачественному товару (Казахстан): человек загружает чек и переписку, система извлекает поля с привязкой к строкам чека, строит хронологию, показывает недостающие доказательства и собирает претензию в DOCX, где каждое число и дата подтверждены фактом.

> Прототип для хакатона SDG Impact 2026. На демо используются только синтетические данные.

## Статус
**Работает:**
- Бэкенд: загрузка файлов, OCR (фикстуры для демо-чека, живой Tesseract `rus+eng` для новых), извлечение полей с grounding (фикстура / OpenAI / rule-based baseline, режим `LLM_MODE=auto`), подтверждение полей, проверки V1–V4, хронология, список недостающего (M1–M5), сборка претензии, выходной guard, экспорт DOCX. Тесты: `pytest -q` → 49 passed.
- Фронтенд: три экрана (загрузка → проверка → претензия), кликабельные суммы/даты с подсветкой строки на чеке, i18n RU/EN, mock- и http-режимы. `npm run build` / `typecheck` / `lint` — зелёные.
- Сквозной сценарий проходит в браузере (mock и http); новый синтетический чек проходит путь до DOCX в режиме `auto` (живой OCR + OpenAI).
- Eval: `python eval/run_eval.py --mode openai|rules` на 9 синтетических делах. Прогон 25.11 (openai, gpt-5.4-mini): сумма 100%, дата 100%, товар 94%, grounding 98%, не найдено дословно 1 из 58 (помечено на проверку), guard 9/9. Синтетика лёгкая для Tesseract, это не цифры для реальных фото.
- Плашка источника данных в UI (Fixture / Live OCR / Live LLM / Rule-based baseline), EN по умолчанию, согласие, удаление дела, mock-сборка без бэкенда (`npm run build:mock`).

**Не сделано / сознательно урезано:**
- OCR на демо — из разметки генератора (`*.layout.json`), а извлечение — рукописные фикстуры (`handmade_*.json`); это **не** результат реального распознавания (см. [docs/DECISIONS.md](docs/DECISIONS.md)).
- Нет: PDF-экспорта (только DOCX), Telegram-парсера (только WhatsApp), проверок V5–V8, PaddleOCR, dark mode.
- Живой Anthropic-провайдер не прогонялся (нет ключа); живой путь идёт через OpenAI. Реальные фото чеков не измерялись.

## Запуск (Windows, 3 команды)
Первая настройка один раз — см. [docs/HANDOFF.md](docs/HANDOFF.md). Затем в двух терминалах:
```
# 1) бэкенд, из корня репозитория
.venv\Scripts\python -m uvicorn app.main:app --reload
# 2) фронтенд, из frontend\
npm run dev
# 3) открыть в браузере
http://localhost:5173
```
Демо-файлы для перетаскивания: `eval\cases\demo-001\` (`receipt.png` → «Чек», `chat.txt` → «Переписка»).

Режим без бэкенда (для жюри): в `frontend\` — `npm run dev:mock` (статическая сборка: `npm run build:mock`, папка `dist-mock/`).

## Режимы извлечения и приватность
`LLM_MODE=fixture|openai|live|rules|auto` (см. `.env.example`). `rules` — это **rule-based baseline** (регулярки), а не LLM. `auto`: известный sha256 чека → фикстуры (офлайн), неизвестный → живой Tesseract + OpenAI (если есть ключ) или rule-based baseline.

**Приватность:** в режимах `openai` и `live` текст OCR чека отправляется внешнему провайдеру (OpenAI / Anthropic). На демо и в eval используются только синтетические данные; реальные чеки в такие режимы подавать нельзя. Содержимое чека и тела запросов не логируются. Сохранение ответов модели в `eval/fixtures/{sha}.json` включается только явно (`SAVE_LLM_FIXTURES=1`).

## Инварианты (нарушать нельзя)
LLM возвращает только значения и `line_ids`; текст и координаты копирует код. Правовые нормы — только из `rules/legal_refs.json` (заглушки). Поле попадает в претензию лишь при `confirmed_by_user=true`. Guard блокирует экспорт при любом числе или дате вне подтверждённых фактов и дат событий.
